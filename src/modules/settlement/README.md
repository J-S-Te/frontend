# 结算与开票前端模块

该模块通过 `/settlement` 进入，API 使用 `/settlement/api/v1`，并保持独立的 Settlement 会话边界。门户是否展示该模块仍以后端应用目录登记为准。

一期页面提供结算总览、应收计划与应收单、开票申请/台账/详情、回款登记、回款核销、核销与冲销、账龄催收及催收策略；金额和状态均以后端事务返回为准，前端不保存账务投影或模拟数据。

## 当前实现约束

- 页面通过当前子系统会话访问 `/settlement/api/v1`，权限只用于菜单和操作可见性，后端仍必须执行最终鉴权和数据范围检查。
- 结算总览按当前页面分区加载目标接口，避免每次切换路由都请求全部模块；请求代次用于丢弃离开页面后的过期响应。单个接口失败不得被误认为业务数据为零，正式环境应展示可诊断的局部失败状态。
- “发起开票申请”的应收下拉只展示已确认、仍有可开余额且未被占用的应收；不通过前端或数据库直接写入模拟应收。联调顺序是合同财务事件→付款条款→应收计划确认→查询可开应收。
- “回款核销”负责登记/确认回款及回款到应收的分配；“核销与冲销”负责查看已生效分配、发起冲销和重新分配，两者不能共用一个会修改历史分配的页面语义。
- 账龄导出走异步 CSV 任务；第一期 TOP10 为应收账龄/未开票读模型，不代表总账事实。
- 返回子系统门户使用统一的关闭子系统标签页并回退到门户路由；退出登录撤销结算本地会话并跳转登录页。OIDC 全局 `end_session_endpoint` 尚未接入，不能在文档中宣称已完成统一退出。

## 验证

```bash
node --test src/modules/settlement/settlement-ui.test.mjs src/modules/settlement/api/settlement.test.mjs
npm run build
cd Settlement && env GOCACHE=/tmp/settlement-go-cache go test ./...
```

数据库业务链路测试默认跳过，需要显式设置 `SETTLEMENT_E2E_TEST=1` 并连接测试数据库；测试必须通过业务 API/事件链路生成应收，不得直接插入应收表。
