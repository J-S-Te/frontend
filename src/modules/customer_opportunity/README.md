# 客户与商机管理前端模块

本模块是 Vue 3 + Vite 的阶段性交付，API 基地址默认是 `/customer-opportunity/api/v1`，可用 `VITE_CRM_PUBLIC_PATH_PREFIX` 或 `VITE_CRM_API_BASE_URL` 覆盖。请求使用同源 HttpOnly Cookie，401 会跳转 `/customer-opportunity/auth/login`。

## 已实现

- 客户列表、详情、查重、创建、编辑、作废/恢复和沟通记录对接真实customer Handler。查重仅披露可见候选；租户唯一性仍检查，范围外冲突只返回受限标记/管理员复核提示。
- 客户查询支持客户号/名称、类型、行业、区域、负责人、状态、创建时间、最近跟进时间的组合筛选，支持 NEW/WON/FOLLOWUP_DUE 快捷筛选、最近跟进与商机金额汇总排序、URL 状态恢复和列表/卡片切换。
- 客户详情按需读取脱敏联系人、关键干系人、信息系统、本地商机、项目、沟通和操作日志；项目服务未配置时只让该页签失败，操作日志按 `customer.audit.read` 显示。重点客户缺少权威分类字段，KEY 在界面禁用，不回退到已删除的信用评级口径。
- 关键干系人与信息系统支持全量维护，仅 `customer.update` 且客户为 `ACTIVE` 时展示入口；写入携带客户版本、变更原因和幂等键，成功后采用服务端 `customer_version` 刷新详情版本。电话/邮箱只展示脱敏值，编辑时省略即保留密文，绝不把脱敏值回填；信息系统保护等级明确为网络安全等级保护定级，不是信用评级。
- 客户 Excel 导入按 `customer.import` 权限显示三阶段向导：只上传 `.xlsx` 与原因，服务端格式和内容结构校验后返回脱敏逐行预检，确认时携带任务版本和幂等键，完成后展示成功/失败/跳过明细并刷新客户列表。新模板为 8 个业务字段，不需要人员或组织 ID；新客户归当前导入人，服务端确认组织，预检展示负责人和组织名称。需交接时使用既有“变更负责人”流程；旧 10 列 ID 模板不得指定其他负责人。CSV 错误报告通过认证请求下载，Object URL 用后立即释放；浏览器不解析或持久化工作簿内容。
- 客户合并向导已接真实 `/customers/merge`：加载目标主档核对，发送源/目标版本、原因和幂等键；Portal 跨库身份映射、补偿任务或已关联合同商机存在时展示后端结构化阻断，不伪造成功。
- 商机列表、详情、创建、普通主档编辑、作废/恢复和阶段调整，对接当前真实 `opportunity` Handler。
- 商机类型与来源从租户目录接口读取并以结构化 ID 多选，不保留前端硬编码回退。销售总监和 CRM 超级管理员可在“基础数据配置”中新增、重命名、排序、启停和删除；已引用项仅可停用，历史停用项继续显示且不能重新添加，目录读取失败时商机表单禁止提交。
- 个人通知中心已接 `/notifications`、`/notifications/unread-count` 与 `/notifications/{id}/read`；页面只呈现当前登录用户收件箱，不使用 SELF/ORG/ALL 扩大通知范围，负责人变更通知可进入现有商机详情。
- 售前预警规则入口遵循 `presale.alert.config`。服务端始终返回六类受支持规则：尚未保存的规则标为 `configured=false`、默认禁用，不在读取时写入数据库；管理员显式保存后才形成配置和版本历史。页面展示未配置、加载、失败重试和保存状态，使用独立数据版本 `version` 做并发校验，不将 `config_version` 当作新版接口的行版本。
- 商机阶段超时告警已接个人列表、已读、租户规则查询与更新接口；规则按钮按 `/auth/me` 的 `opportunity.alert.config` 权限显示，并对后端 403 单独提示。
- 阶段告警页面展示起算时间、到期时间、阈值版本和状态释义。当前后端个人查询只返回 `UNREAD/READ`；`PENDING/CANCELLED` 仅解释其生命周期，不伪造查询结果。
- 阶段使用中文枚举：初步接触、需求沟通、方案制定、报价、投标、已签约、失败；调整立即生效，不展示审批中间态。
- 售前申请创建、内部审批、当前指派、执行人替换、进度登记和工时登记均在客户与商机系统内完成。
- 两级执行指派按服务端状态与 `assignment_actions` 渲染：技术总监在待指派状态选择执行部门和团队负责人，团队负责人候选按所选组织从 owner-directory 分页过滤；只有被选中的团队负责人在待执行指派状态看到执行人入口和拒绝入口。执行人入口调用独立 `executor-assignments` 接口，支持为每人选择技术工程师/项目经理/团队负责人角色。
- 团队负责人待办、技术总监拒绝/失效通知和待团队负责人指派超时预警均显示中文文案；前端不把通知或预警当作业务授权，点击后仍由售前详情接口复核数据范围。
- 售前Actor当前使用平台user_id执行，DTO保留person_id命名，不要求PMS身份映射。执行人从基础平台当前有效且已授权给本应用的用户目录选择；前端不手填 ID，后端重新校验用户并保存权威姓名和组织快照。
- 售前候选目录按 `assignment_duty=TEAM_LEAD/EXECUTOR` 查询，CRM 代理从现有权限目录计算角色过滤后再分页；不由前端硬编码资格角色或自动赋权。执行人稳定重试载荷保留明确选择的 `department_id`，展示姓名、组织名称不参与请求意图；保存端继续复核。
- 新指派角色只接受 team_lead、project_manager、technician；implementation_engineer 仅兼容历史记录，并在替换前展示新增、保留和移出差异；工时支持 `HOUR` 和 `PERSON_DAY`，页面明确 1 人天 = 8 小时。
- 当前“结束进度”按 available-actions 展示，服务端检查执行中状态、版本、当前指派、person_id、执行角色和 presale.complete；没有全员至少一笔工时的前置条件。
- 售前超时预警已接规则配置、个人列表和已读接口；申请销售/CRM 角色收件人使用 `USER/user_id`，TS-008执行人预警保留历史PERSON字段协议；新指派/过程通知已显式USER，两条链分别按服务端规则读取，前端不推断身份映射，也不会因 SELF/ORG/ALL 数据范围扩大。站内消息由独立 `customer-presale-alert-worker` 投影，未配置外部 IM/短信/邮件发送。
- 新建售前申请的需求说明只校验去除首尾空白后非空，不再设置 10～2000 字限制；所有必填项显示星号，并由后端执行最终校验。
- 售前详情已接独立的稳定 cursor 流程时间线和 `available-actions`：事件类型、状态、审批结果、场地与紧急度统一显示中文，进度链接只开放再次校验通过的 HTTPS 地址；操作区以服务端独立响应为唯一权威，加载失败时安全关闭变更入口。通过/驳回按钮由服务端核对实例/节点/角色后出现；默认未启用外部待办解析器，内部审批同事务记录；显式启用APPROVAL_TASK_RESOLVER_ENABLED则接外部任务/回调，浏览器不接收或提交内部 `engine_task_id`；指派、审批、取消、进度、工时及投递重试后会刷新详情、时间线和可用操作，不重置当前列表筛选与分页。
- 售前审批、完整指派替换、执行部门/团队负责人、执行人替换、拒绝执行指派和取消在页面内按“任务 ID + 操作 + 规范化载荷”分别保存结果未确认的重试键：同一请求复用原 `Idempotency-Key`，载荷或任务变化只为新命令创建新键，不会驱逐旧命令；只有对应请求获得服务端成功响应才清理。prompt 取消和前置校验失败不分配键，关闭或切换任务仍在当前页面生命周期内保留未确认项；页面卸载统一释放。键不会写入 localStorage、sessionStorage 或 URL，因此整页刷新后的结果歧义须先核对服务端状态。
- TS-007 列表已接真实状态看板和服务端筛选选项：列表/只读看板共用完整筛选，视图、分页和每列上限可从 URL 恢复；不传授权 `scope`，选项失败即清空，看板显示服务端 total 与截断数量。快速切换筛选或视图时，递增请求序列会丢弃过期响应，避免旧数据覆盖当前页面。
- 售前投入报表已接入 `summary/trend/distribution`，支持 UTC 周期、组织/人员/商机和人员/部门/商机分布筛选，显示标准小时 KPI、分布图及等价数值表。

## 阶段性限制

- 两级执行指派的团队负责人待办/拒绝/失效通知和超时预警已接线；人员交接模块已隔离 `TEAM_LEAD` 与执行责任，负责人转移要求技术总监重选，自动转移未实现。已在现有本地栈完成真实浏览器、基础平台 owner-directory 和站内消息投影联调；完整 PMS 同步任务、外部渠道和生产部署仍未验收。
- 商机附件详情已接入 capability 和服务端代码安全校验；服务端执行大小、MIME、SHA-256、路径、归档展开体积、图片像素和内容格式校验，只有返回 `CLEAN` 且当前会话有独立下载权限时才可下载。报价/投标主动查询和最长 5 分钟的服务端固定地址签名调起已接入，正式 Client、mTLS 证书、地址及外部 nonce 消费未配置时失败关闭。合同客户重绑和外部报价/投标关联迁移仍未实现，前端不伪造这些能力。
- Excel 导入使用进程内静态校验和有界 XLSX 解析，不再使用病毒引擎；前端不会绕过校验或伪造预检结果。静态校验不能保证检测所有恶意文件。
- 客户项目历史有可选HTTP适配器，由PORTAL_PROJECT_HISTORY_ENABLED装配；未配置返回结构化503。客户导入默认使用代码级 XLSX 防护，客户导出由 CRM 请求内生成 CSV 临时文件并在响应后删除，不使用 OSS 或导出 Worker。
- 商机负责人和当前团队已接真实读写接口；团队加入、移出、重新加入和角色变化另有独立分页任期账本。`LEGACY_SNAPSHOT` 显示迁移观察时间与当时是否在组，明确标注迁移前加入/移出时间未知；不伪造一段连续任期。任期请求用商机与请求序列双重校验，快速切换时新商机不会被旧 loading 锁住，旧响应也不会覆盖。负责人选择已按正式契约接通平台目录：CRM `GET /api/v1/owner-directory` 只返回内部有效 OIDC `sub`、显示名及其 CRM 授权组织成员关系，不返回账号/邮箱/手机/PMS `person_id`；`OwnerSelector` 先选人员再联动可选组织，默认取当前登录人的主组织，目录不可用或无权限时失败关闭，绝不回退到手工输入的任意 ID。
- 负责人变更、售前审批/指派/进度/完成等通知均在同一事务生成 outbox，并由统一 Worker 投影到 CRM 个人站内收件箱；两级执行的团队负责人待办、技术总监拒绝/失效通知由服务端事务直接写入本地站内消息，同样进入个人收件箱；另有notification-delivery-worker把CRM消息同步到平台中央收件箱；不承诺IM、邮件或短信。
- 人工进入“已签约”调用合同归属校验；CONTRACT_VERIFICATION_ENABLED开启时bootstrap注入真实HTTP校验器，未开启才返回INTEGRATION_CONTRACT_NOT_CONFIGURED。必须核对目标环境配置与同客户合同。
- 售前报表异步导出依赖导出 Worker、对象存储和受控下载；后端当前明确返回 `CRM_PRESALE_REPORT_EXPORT_UNAVAILABLE`，页面不会伪造文件。
- 本模块已由统一前端公共 `moduleRegistry.js` 与 `router/index.js` 注册，并使用独立 CRM OIDC 服务端会话。

售前完成路径补充：单独登记工时不自动完成，人工“结束进度”不要求工时；但保存完整指派替换后，后端会对全部当前执行人已有的本任务未作废工时重新判断，满足条件可立即自动完成。指派成功后须按返回状态刷新，不固定假定仍执行中。

不要在前端补演示数据或绕过后端权限。后端 401、403、409 和业务错误是最终边界。

## 用户操作与验证边界（2026-10-22）

入口从基础平台应用目录进入CRM的/auth/login，再到客户/商机/售前等栏目。客户信用详情、信用审批待办与信用规则管理已接credit API，不使用旧原型“信用已删除”口径。普通销售不默认拥有导入/导出/合并权限；应以会话权限和服务端角色条件为准。

客户导入只接XLSX八列模板、10MiB/1000行、30分钟预检；WARNING本次跳过。客户导出是当前数据范围CSV，后端没有按当前列表筛选载荷导出。附件20MiB与PDF/PNG/JPEG/DOCX/XLSX白名单由后端最终确认，CLEAN是静态校验结果。

新工时只存CRM，页面SUCCESS不表示PMS已收到，登记后仍为执行中；结束进度是单独按钮。审批没有单独凭据输入框或发起人自审排除规则，角色+权限+实例状态共同决定；浏览器不提交engine_task_id。信用审批不是售前节点审批，不能复用其规则或幂等保障。

步骤、成功判断和失败处理见 [CRM操作手册](../../../../sharedDocs/10_操作手册/客户与商机管理操作手册.md)；完整源链与原陈述纠正见 [核验记录](../../../../.ai/modules/operation-docs-crm-20261013.md)。本轮未执行npm test/build或浏览器验收。

当前指派候选与保存复核共用已发布目录职责映射：负责人presale.assign，执行人同时presale.progress/worklog/complete；缺资格422，目录不可用503，不自动补授权。执行中可通过execution-takeover由技术总监/超管受控接管同部门合格负责人，使用版本和稳定重试键，保留执行人集合；人员交接仍不自动转移TEAM_LEAD。审批通知按started_at轮次去重，重开不复用旧通知。迁移000121标记新USER指派/过程通知，未标记历史仅在两种已认证身份相同时兼容，不全量猜测回填。
